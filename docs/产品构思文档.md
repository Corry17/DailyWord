# DailyWord — Mac 菜单栏背单词应用 · 产品构思文档

> 版本：v0.4（构思稿）
> 日期：2026-08-13
> 定位：一款专属于 macOS 的**菜单栏常驻**背单词工具，面向**考试备考**（四六级 / 考研 / 雅思 / 托福），**核心学习完全离线可用**，学习进度通过**快照文件 + 同步文件夹（iCloud Drive 等）**实现多端同步，无需 Apple Developer 账号。

---

## 1. 产品定位

### 1.1 一句话描述

把背单词塞进菜单栏：不用切换应用、不用打开网页，点一下菜单栏图标就能背几个词，用碎片时间完成每日任务。

### 1.2 目标用户

- 备考四六级、考研、雅思、托福的学生 / 在职考生
- 长时间使用 Mac（写论文、写代码、办公），希望利用碎片时间背单词的人

### 1.3 核心痛点与解法

| 痛点 | 现有产品的问题 | 我们的解法 |
|------|--------------|-----------|
| 背单词要专门打开 App/手机，仪式感太重容易放弃 | 手机 App 打开后容易刷别的 | 菜单栏一键呼出，3 秒进入学习状态 |
| 工作/学习间隙的碎片时间被浪费 | 网页版词典/背单词工具需要切换窗口 | 常驻菜单栏 + 全局快捷键呼出 |
| 忘了复习，艾宾浩斯曲线形同虚设 | 提醒靠手机推送，容易被淹没 | macOS 原生通知 + 菜单栏图标角标提示到期复习数 |
| 没网就没法背 | 多数产品强依赖网络 | 词库、释义、发音全部本地离线 |

### 1.4 差异化卖点

1. **原生轻量**：SwiftUI 原生开发，安装包小、内存占用低、启动即用。
2. **零打扰融入工作流**：菜单栏 Popover 形态，背完即走，不抢占屏幕。
3. **完全离线**：内置考纲词库 + 离线词典 + 系统 TTS 发音，飞机上也能背。
4. **科学复习**：内置 FSRS/SM-2 间隔重复算法，自动安排复习队列。

## 2. 核心功能设计

### 2.1 功能总览（按优先级）

| 优先级 | 功能 | 说明 |
|-------|------|------|
| P0 | 菜单栏 Popover 学习卡片 | 核心学习界面：看词 → 回忆 → 翻面 → 自评 |
| P0 | 考纲词库 | 内置 CET-4 / CET-6 / 考研 / 雅思 / 托福词表 |
| P0 | 间隔重复复习（SRS） | 艾宾浩斯遗忘曲线阶梯（30分钟→12小时→1天→2天→4天→7天→15天→30天），自动生成每日"新学 + 复习"队列 |
| P0 | 无感式复习 | 到期单词自动在屏幕角落弹出免打扰浮卡（不抢焦点、限时消失），承接曲线的当天内复习节点 |
| P1 | 修仙路游戏 | 修仙主题爬塔背单词：16 大境界、5 职业 + 隐藏职业魔修、答题战斗、装备/随从/图鉴、成就联动（详见《游戏设计文档》） |
| P0 | 首次启动引导 | 13 步介绍入口、学习、词库、练习、设置、移动、关闭、翻译、成就、游戏与备份；完成或勾选不再显示后停止自动展示，可从菜单/设置重看 |

| P0 | 发音 | 系统 AVSpeechSynthesizer（TTS），英音/美音可选 |
| P1 | 每日学习计划 | 设定考试日期 + 每日新词量，自动推算进度 |
| P1 | 学习统计 | 打卡日历热力图、已学词数、记忆保持率曲线 |
| P1 | 复习提醒 | 菜单栏角标显示到期数量 + 定时系统通知 |
| P1 | 全局快捷键 | 如 ⌥Space 呼出学习卡片 |
| P2 | 生词本 | 手动收藏、标记"太简单"直接斩词 |
| P2 | 多种练习模式 | 英译中选择题、中译英拼写、听音辨词 |
| P2 | 划词收藏 | 系统服务/快捷键取词，把任意 App 中选中的单词加入生词本 |
| P2 | 多端同步（基于文件） | 学习快照自动写入同步文件夹（iCloud Drive/坚果云等），其他设备自动合并，无需开发者账号 |
| P2 | 数据导入导出 | 手动 JSON 备份/恢复（同步方案的基础能力，也是兜底） |

### 2.2 学习流程（核心闭环）

```
每日打开
   │
   ▼
菜单栏图标（显示今日待学/待复习角标，如 ●23）
   │ 点击 / 全局快捷键
   ▼
Popover 卡片队列 = 到期复习词（优先） + 今日新词
   │
   ▼
单卡交互：
  正面：单词 + 音标 + 发音按钮（自动/手动发音）
  [空格] 翻面
  背面：释义 + 例句 + 词性 + 考纲标签
  自评四键：1 忘记 / 2 模糊 / 3 记得 / 4 太简单
   │  （自评结果喂给 SRS 算法，计算下次复习时间）
   ▼
队列清空 → 今日完成页（打卡 + 统计小结）
```

**交互原则：全程可纯键盘操作**（空格翻面、1-4 自评、Esc 关闭），符合 Mac 用户习惯。

### 2.3 界面结构

应用只有两个界面层级，保持轻量：

1. **菜单栏 Popover**（日常 99% 的使用场景）
   - 学习卡片视图（上述核心闭环）
   - 顶部小条：今日进度（如 `新词 8/20 · 复习 15/23`）
   - 底部工具条：暂停、跳过、打开主窗口、设置
2. **主窗口**（低频使用，管理性质）
   - 词库管理：选择考纲词表、查看词表进度
   - 学习计划：考试日期、每日新词量、提醒时间
   - 统计页：热力图、曲线、总览数字
   - 生词本：收藏列表、搜索、批量操作
   - 设置：发音口音、快捷键、外观（跟随系统深浅色）

### 2.3.1 上手引导（当前实现）

- **完整路径**：欢迎 → 菜单栏 → 翻面/自评/发音 → 词库/详情 → 练习 → 设置 → 透明度 → 面板移动 → 关闭/呼出 → 翻译 → 成就/复习提醒 → 修仙路 → 数据备份与帮助。
- **可选互动**：自评、答对一题、调整透明度、快捷键移动面板、三连击关闭后给出反馈并短暂延迟推进。所有步骤始终保留上一步、下一步和结束按钮，无词/未绑定快捷键/未完成互动均不会阻塞教程。
- **演示数据隔离**：学习、选择/拼写练习、透明度、移动和三连击均在独立示例面板操作，只更新内存状态；不启动真实学习队列、不记录排期/XP、不持久化演示外观或位置。词库与设置仍是正式界面，主动修改会生效；翻译、修仙路和导入导出只做说明，不自动读取选区、请求权限、开局或导入。
- **快捷键与入口**：展示当前配置而非硬编码默认值，区分全局、面板内和未设置；翻译说明为“主动打开翻译窗口后选中刷新，关闭后停止跟随”。
- **退出与重看**：完成后记住已完成；结束引导时按“下次启动不再自动显示”勾选状态决定是否再次自动展示。气泡获得焦点后 Esc 可结束。进行中的重复打开只聚焦当前引导，结束后重看从欢迎页开始。
- **生命周期保护**：切步、后退、退出和重开使旧任务令牌失效，取消待执行的展示/自动推进；鼓励反馈不重新打开目标面板、不抢输入焦点；仅清理引导自动打开的窗口，保留用户原先打开的界面。
- **布局与恢复**：气泡跟随实际目标窗口所在屏幕，移动/缩放后重新定位；没有锚点或空间不足时居中且不画误导箭头。正文可滚动、导航固定；目标被关闭时可“重新显示本步界面”。
- **回归覆盖**：步骤边界、完整手动导航、重复互动、过期回调、任意步骤退出、演示状态隔离、菜单栏贴边、负坐标副屏与缺失锚点均纳入 `TestRunner`；原生窗口焦点和多屏实机显示仍需交互验收。

### 2.3.2 翻译与窗口稳定性（当前实现）

- 翻译仅在用户主动打开的会话内工作；关闭会话后停止监听并取消取词/网络请求，迟到回调不能新建窗口。
- 每次新选中或显式重试均产生独立请求令牌；取词结果、逐句结果、失败结果均校验令牌。快速 A→B→A 也只显示最后一次请求，不用 2/3 秒冷却阻挡新词。
- 普通单击/右键不读取旧剪贴板；拖选/多击或键盘选区变化优先走后台 AX。识别后先显示原文与“翻译中…”。没有识别结果时不把旧剪贴板作为选区。
- AX 不可用时，复制兼容路径固定源应用 PID、串行执行，仅读取本次复制后新增的剪贴板变化；保留原剪贴板各格式，期间用户再次复制或剪贴板另有变化则放弃恢复，避免覆盖新内容。真实 ⌘C 的兼容更新以观察到该键后的计数变化为依据，而非推断旧内容的时间。
- 移除无条件遍历 Acrobat 的脚本及重复发送复制按键；后台 AX 读取有限时和遍历上限。此项不等于已经解决所有 PDF 识别，Acrobat/Preview 的实际选区仍需逐环境验收。
- 设置窗口在锚点左侧无空间时尝试右侧，并按目标屏幕可视区域钳制；设置和学习提示读取当前快捷键。
- 词根表统一在 `WordRootCatalog` 中维护，清理重复键，初始化与覆盖校验加入测试。

### 2.3.3 快捷键与数据备份安全（当前实现）

- 练习面板快捷键按键码与四个核心修饰键精确匹配；不再将同键码的其他组合误当为已配置动作。未匹配的 Command/Control/Option 组合不写入拼写答案、不触发选择题判分。
- 快捷键录制期间暂时释放全局绑定；Esc、失焦和关闭设置仅取消录制，保留原绑定。与其他动作冲突时，对方持久化为“未设置”，重启后不会被默认值恢复；用户自定义修饰键不再自动改写。
- 学习/练习面板移动监听随面板关闭注销，窗口焦点监听重新挂载前先移除，关闭回调随窗口释放并校验窗口身份。
- 导出词库卡片、复习流水与每日统计使用同一数据库快照；空删除时间显式编码为 JSON null；写文件使用原子替换。设置备份包含每日新词数量。
- 导入先检查应用标识、版本、分组、字段类型、数值范围和快捷键格式；损坏的日期、二进制及嵌套 null 不写入设置或数据库。
- 卡片、流水和每日统计统一在一个事务导入，数据库任意环节失败全部回滚；数据库成功后才应用已校验的设置。此保证针对正常校验/写入错误，不是 SQLite 与 UserDefaults 跨存储的断电原子提交。
- 同词本地卡片优先，备份仅补缺失条目，不以更高熟练度覆盖用户的本地重置；复习流水按 UUID 去重，关联到本地卡片；同日统计取较大值，防止旧备份降低进度。未知词条导致外键失败时整批拒绝，不静默跳过。
- 回归测试覆盖备份往返、旧 0 删除标记兼容、重复导入、故障注入回滚、设置不被部分覆盖和快捷键冲突恢复；UI 录制与多窗口焦点仍需实机验收。

### 2.4 SRS 复习算法

- 首选 **FSRS**（Free Spaced Repetition Scheduler，Anki 新一代算法），有开源 Swift 移植可参考；实现成本高则先用 **SM-2** 起步，算法层抽象成协议方便后续替换。
- 每个单词维护：熟练度状态（新词/学习中/复习中/已掌握）、难度、稳定性、下次复习时间。
- "太简单"支持直接斩词（跳出队列，可在生词本恢复）。

## 3. 技术方案

### 3.1 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| UI | SwiftUI + `MenuBarExtra`（macOS 13+） | 官方菜单栏应用 API，声明式开发快 |
| 主窗口 | SwiftUI `Window` / `Settings` scene | 与 Popover 共享视图组件 |
| 数据库 | SQLite + [GRDB.swift](https://github.com/groue/GRDB.swift) | 词库量大（考研 5500+，雅思 8000+），需要高效查询；GRDB 成熟稳定。备选 SwiftData（量大时性能存疑） |
| 词典数据 | 多个开源数据源融合（见 3.2） | 主词典 ECDICT + 例句、同义词、词频等多源增强 |
| 多端同步 | 快照文件 + 同步文件夹（iCloud Drive 作为普通目录使用） | 不依赖 CloudKit，**无需 Apple Developer 账号**；兼容坚果云/Dropbox 等任意同步盘 |
| 发音 | `AVSpeechSynthesizer`（en-US / en-GB） | 系统自带，零成本离线；P2 可选接入本地音频库 |
| 通知 | `UserNotifications` | 复习提醒 |
| 全局快捷键 | `KeyboardShortcuts`（sindresorhus 开源库） | 免去 Carbon API 手写 |
| 自动更新 | [Sparkle](https://sparkle-project.org/)（开源） | dmg 直接分发必备的应用内更新框架 |
| 最低系统 | macOS 13 Ventura | `MenuBarExtra` 要求；不再受 CKSyncEngine 限制 |

### 3.2 开源词汇与例句数据源

原则：**能引入的开源数据尽量引入**，在离线预处理阶段融合成一个 words.sqlite，运行时零网络依赖。

| 数据源 | 许可 | 提供什么 | 用途 |
|--------|------|---------|------|
| [ECDICT](https://github.com/skywind3000/ECDICT) | MIT | 77 万词条：音标、中英释义、柯林斯星级、词频、考纲标签（cet4/cet6/ky/ielts/toefl） | **主词典**，考纲词表切分的依据 |
| [kajweb/dict](https://github.com/kajweb/dict) | 开源词书 JSON | 四六级/考研/雅思/托福等成套词书，自带例句和例句翻译 | 考纲词表校对 + 例句补充 |
| [Tatoeba](https://tatoeba.org/) | CC-BY 2.0 FR | 数百万条人工翻译的英中句对 | **主例句库**：按单词索引例句，优先选短句、含中文翻译的句子 |
| [WordNet](https://wordnet.princeton.edu/) | WordNet License（宽松） | 英文释义、同义词/反义词、上下位词 | 英英释义、同近义词辨析 |
| [CMU Pronouncing Dictionary](https://github.com/cmusphinx/cmudict) | BSD | 13 万词的音素级发音标注 | 校对/补全音标数据 |
| Wiktionary dumps | CC BY-SA 3.0 | 词源、变形（复数/时态）、用法说明 | 词形还原（划词取词时把 running → run）、词源助记 |
| [FrequencyWords](https://github.com/hermitdave/FrequencyWords)（OpenSubtitles 语料） | CC-BY | 真实语料词频表 | 排序词表、优先学高频词 |

预处理流水线（Tools/dict-builder）：

```
ECDICT CSV ─┐
kajweb 词书 ─┤
Tatoeba 句对 ─┼─→ 清洗/对齐/按考纲标签筛选 ─→ 每词挑选 2~3 条最佳例句 ─→ words.sqlite（打包进 App）
WordNet     ─┤     （词形还原对齐、去重、       （短句优先、含中文翻译、
cmudict     ─┘       许可信息保留）               覆盖高频义项）
```

注意事项：
- 各数据源许可（MIT / CC-BY / CC BY-SA / BSD）均允许打包分发，但需在 App「关于」页保留署名和许可声明；Wiktionary 的 CC BY-SA 有传染性，其数据单独建表隔离。
- 词库体积目标：考纲词全集 + 例句控制在 **50MB 以内**；若超出，例句库可拆成可选下载包。

### 3.3 数据模型（草案）

```
Word            词条（来自 ECDICT 预处理）
├─ id, headword, phonetic_us, phonetic_uk
├─ definition_cn, definition_en, pos
├─ tags (cet4/cet6/ky/ielts/toefl), frequency, collins_star
├─ definition_wordnet, synonyms, lemma      ← WordNet / Wiktionary 增强
└─ (关联 Example 表：每词 2~3 条例句)

Example         例句（来自 Tatoeba / kajweb，只读）
├─ word_id, sentence_en, sentence_cn
└─ source, license

WordBook        词书（考纲词表）
├─ id, name (如"考研核心词汇"), tag_filter
└─ word_count

StudyCard       学习卡片（用户 × 单词 的学习状态）
├─ word_id, book_id
├─ state (new / learning / review / mastered / suspended)
├─ difficulty, stability, due_date      ← SRS 参数
├─ review_count, lapse_count
└─ created_at, last_reviewed_at

ReviewLog       复习记录（喂给 FSRS 优化 & 统计用）
├─ card_id, rating (1-4), reviewed_at
└─ elapsed_days, state_before

DailyStat       每日统计
└─ date, new_learned, reviewed, time_spent
```

**同步边界**：词库（Word / Example / WordBook）是打包的只读数据，**不同步**；用户数据（StudyCard / ReviewLog / DailyStat / 生词本 / 设置）参与同步。所有用户表从第一天起就带 `uuid` 主键、`modified_at` 时间戳和软删除标记，为快照合并提供依据。

### 3.4 多端同步方案（免开发者账号）

不使用 CloudKit，改用**快照文件 + 同步文件夹**：本地 SQLite 为唯一真相，定期导出快照到用户指定的同步目录（如 iCloud Drive，即 `~/Library/Mobile Documents/com~apple~CloudDocs/`，作为普通文件夹读写无需任何 entitlement），由云盘自行完成跨设备传输。

```
本地 dailyword.sqlite（真相，不进同步目录）
   │ 每次学习结束 / 定时
   ▼ 导出
同步文件夹/DailyWord/
   ├─ device-A.snapshot.json   ← 每台设备写自己的快照，互不覆盖
   └─ device-B.snapshot.json
   │ 启动时 / 定时扫描到其他设备的新快照
   ▼ 合并导入
本地 dailyword.sqlite
```

关键设计：
- **每设备一个快照文件**（以设备 ID 命名），只写自己的、读别人的，从根本上避免云盘写入冲突；绝不把运行中的 SQLite（含 WAL）放进同步目录，防止半写入状态被同步导致损坏。
- **合并策略**：`ReviewLog` 是只追加流水，取并集即可，零冲突；`StudyCard` / 生词本 / 设置按 `modified_at` 取较新一方（last-writer-wins）；删除靠软删除标记传播。
- **体验分三档逐步实现**：① 设置页手动导出/导入（M2）→ ② 指定同步文件夹后自动写快照（M3）→ ③ 自动扫描并合并其他设备快照，接近无感同步（M3）。
- 局限：非实时（iCloud Drive 传输通常秒级到分钟级），对背单词场景完全够用；未来若购买开发者账号，可在此基础上平滑升级 CloudKit（数据模型已兼容）。

### 3.6 分发方案（dmg 直接分发，暂无开发者账号）

- **现阶段（无账号）**：自用直接编译运行；分享给少量朋友时，对方首次打开需右键→打开（或 系统设置→隐私与安全性 放行），在 README 里说明即可。
- **未来升级（购买账号后）**：Developer ID 签名 + `notarytool` 公证，Gatekeeper 不再拦截；此升级不影响已有代码。
- **打包**：`create-dmg` 生成带拖拽安装界面的 dmg。
- **应用内更新**：集成 Sparkle，appcast.xml 托管在 GitHub Releases / 静态站点，用户无需重新下载 dmg 即可升级。
- **CI**：后期可用 GitHub Actions 自动完成 构建 → 打 dmg → 发布 Release（签名公证环节留到有账号后接入）。

## 3.7 修仙路游戏模块（已实现 · 详见《游戏设计文档》）

> 完整设计见 [游戏设计文档](游戏设计文档.md)。此处为需求级摘要，功能变更需同步两份文档。

### 需求摘要

- **形态**：菜单栏应用内独立窗口，⌥G 快捷键开关，顶栏三击关闭（自动保存进度）
- **玩法**：选择职业踏上修仙路 → 16 大境界一命通关 → 地图节点（战斗关卡组 2~5 关连战/分叉口三路线/精英/限时/灵泉/商人）→ 四种题型答题战斗 → Boss 镇守
- **职业**：5 个普通职业（剑士/法师/行者/医者/赌徒）+ 隐藏职业魔修（1/1000~1/10 概率随机觉醒，周泰式不屈技能，专属红黑界面）
- **魔器**：😈 隐藏品质装备，信息全部以 ? 示人，仅魔修可见，地下墓穴（1/1000 关卡）胜利 1/50 掉落
- **随从**：宠物/精灵（非装备），独立持久血量（饱食度/灵力），撤退会受伤
- **经济**：金币、神秘商人、云间商城、图鉴收集、装备耐久按品阶磨损
- **成就联动**：游戏成就（初入仙途/首战告捷/十战十胜）计入主等级 XP
- **性能**：词库启动预热 + 分类缓存，进出关卡零卡顿

- [x] 词库与主学习模块打通（已背优先出战、难度滑动窗口）
- [x] 游戏进度随窗口关闭自动保存，战斗倒计时暂停/恢复
- [x] 隐藏职业/魔器概率符合设计（1/1000、1/10、1/50）
- [x] 战斗节点 = 关卡组（2~5 关连战、组进度 HUD、组通关奖励/回血）
- [x] 分叉口三路线（险路/平路/秘路差异化、已走路线灰显）
- [x] 随从不叫"装备"（携带/召回/饱食度/灵力）
